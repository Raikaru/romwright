## Limits

- C++ lane. The 149 game units are C++ (`-lang c++`, mangled symbol names, classes); candidates are C. Each candidate is written as a `.c` file at the unit's place so the unit's own command (`scripts/build/mwccgap.sh`, `-O3,p`, the repo's include roots) compiles it as C, and its function carries the retail mangled symbol name (a valid C identifier). The context is the repo's own C-compatible m2c context (`ctx.c` from `scripts/build/cmake.sh ctx`: classes flattened to structs, no member-function prototypes), the same text for every function. No per-function `#pragma` state is replayed and there is no `oracle` layer (a C++ method's text cannot be compiled as C).
- Satan's Fiddle (the repo's LLDB-based MWCC state controller) is not built here: it needs LLDB development files (fetchable without root, `dnf download lldb-devel`, but the Fiddle revision the repo pins is built against LLVM 19, the host has 22) and an unstripped i386 `wibo` built from source (no 32-bit libc development files on the host and no root). The pinned compiler runs unmodified through `tests/m22-003/tools/satansfiddle-plain`, so the matched set is what plain MWCC 3.0-011126 reproduces: the 79 functions that differ out of the repo's 6747 C functions bound what Fiddle's per-unit overrides recover.
- romwright prints a C++ symbol demangled (`ClsMes_SetHalfFontWPercent` for `SetHalfFontWPercent__6ClsMesFf`); the harness renames the function the text defines to the retail mangled symbol (as m22-002 does for stock Ghidra's names), nothing else in the text is changed.
- The matched set is the decompilation's own: its sources were written against the retail bytes, often with m2c in the loop, so the m2c column is an upper bound on unseen code, as m22-002 says of Persona 4's promoted units.
- Per-function `#pragma` state (MWCC) is replayed from the unit's source for every layer; `#if` branches by m22-002's fixed rule. ee-gcc units have no per-function pragma state.
- Each candidate is compiled twice with the unit's own compile command: `context` (the unit's own declarations as the compiler sees them, m22-002's context rule) and `standalone`; `best` is the better of the two. Percent is objdiff-cli `match_percent` with `functionRelocDiffs=none`; exact is same length and every byte equal outside the object's relocation fields.
- The comparator masks the relocation fields the object declares; it does not check that a relocation's symbol resolves to the retail operand (m22-002's `exact_symbols` is not computed in the generic path).
- The sample is up to 200 functions; sign tests treat functions as independent although they share units, so p values are indicative.
- m2c reads splat assembly generated from the retail ELF for the sampled functions (names from the repo's symbol files, gp-relative operands and jump tables adapted as m22-002 does), with call and gp symbols taken from the object's relocations.
- romwright's import of the retail ELF is one project per lane; a matched function the import did not discover has no `export-c` candidate.
